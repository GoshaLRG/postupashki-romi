# Marketing data model

Контракт между блоками решения. Все модули пишут и читают эти сущности
и только их. Если поля не хватает — сначала правка этого файла, потом код.

## Цепочка

```
marketing activity  →  user touch  →  lead  →  payment  →  revenue
   ad_registry          touch          lead     payment     order
   post_registry
```

Для каждого события должно быть однозначно понятно:
**кто → что сделал → когда → откуда пришёл → к какой рекламной активности относится.**

## Ключ связи всех слоёв

```
user_hash = SHA256(telegram_user_id || salt)
```

Соль хранится вне репозитория и вне выгрузок. Персональные данные
(username, телефон, имя) в хранилище не попадают: для всей аналитики
достаточно анонимного идентификатора. Выданный `student_id` устроен
ровно так же, то есть новая система стыкуется с историческими данными.

## Сущности

### `ad_registry` — журнал внешних размещений

Заполняется вручную или полуавтоматически **до** публикации.
Без `publication_time` и `cost` размещение считается неизмеримым, и ROMI
для него не считается — это правило, а не пожелание.

| Поле | Тип | Обязательное | Комментарий |
|---|---|---|---|
| `placement_id` | str | да | PK, формат `c{channel}_p{placement}_cr{creative}` |
| `channel_id` | str | да | канал размещения |
| `campaign_id` | str | да | кампания (запуск, распродажа, вечнозелёный трафик) |
| `creative_id` | str | да | вариант креатива |
| `publication_time` | datetime | да | без него нельзя привязать всплеск |
| `cost` | decimal | да | стоимость размещения, руб. |
| `format` | str | нет | пост / кружок / нативная интеграция |
| `is_synthetic` | bool | да | пометка тестовых данных |

### `post_registry` — журнал публикаций в своём канале

| Поле | Тип | Комментарий |
|---|---|---|
| `post_id` | str | PK |
| `ts` | datetime | время публикации |
| `post_type` | enum | `sale` / `discount` / `native` / `content` / `launch` |
| `discount_pct` | float | глубина скидки, если есть |
| `campaign_id` | str | к какой кампании относится |

### `touch` — касание пользователя

Пишется ботом автоматически. Это единственный слой, который сейчас
полностью отсутствует и из-за которого воронка — чёрный ящик.

| Поле | Тип | Комментарий |
|---|---|---|
| `touch_id` | str | PK |
| `user_hash` | str | см. выше |
| `placement_id` | str | из payload диплинка, NULL для органики |
| `campaign_id` | str | денормализовано для скорости |
| `ts` | datetime | время касания |
| `touch_type` | enum | `click` / `bot_start` / `channel_join` |
| `is_synthetic` | bool | пометка тестовых данных |

### `lead` — начало диалога с менеджером

| Поле | Тип | Комментарий |
|---|---|---|
| `lead_id` | str | PK |
| `user_hash` | str | связь с `touch` |
| `ts_first_message` | datetime | момент первого сообщения |
| `product_interest` | str | какой курс спрашивал |
| `manager_id` | str | кто вёл |

### `order` / `payment` — то, что есть уже сейчас

| Поле | Тип | Комментарий |
|---|---|---|
| `order_id` | str | PK, хеш от `student_id` + `ts` |
| `user_hash` | str | = `student_id` в текущей выгрузке |
| `ts` | datetime | момент оплаты и выдачи доступа |
| `revenue` | decimal | сумма строк заказа |
| `n_items` | int | курсов в заказе |

| Поле | Тип | Комментарий |
|---|---|---|
| `payment_id` | str | PK, строка заказа |
| `order_id` | str | FK |
| `course` | str | курс |
| `amount` | decimal | сумма строки |
| `discount_code` | str | промокод, если был — сейчас не логируется |

## Что связывает слои

| Переход | Механизм | Работает сейчас |
|---|---|---|
| размещение → касание | `placement_id` в payload диплинка | нет |
| касание → лид | `user_hash` | нет |
| лид → оплата | `user_hash` | нет |
| оплата → выручка | `order_id` | да |

## Если детерминированная связка невозможна

Пользователь может прийти из рекламы, месяц читать канал и написать
менеджеру без перехода по ссылке. Тогда `touch` не создаётся и
детерминированного стыка нет. Правила на такой случай:

1. Менеджер задаёт вопрос «откуда узнали» — низкая точность, но лучше нуля;
   ответ пишется в `lead.source_declared` как отдельное поле с пометкой
   `self_reported`.
2. Оплаты без единого касания в окне атрибуции относятся в сегмент
   `organic / unattributed` и **не** распределяются между каналами.
   Раздувать атрибуцию догадками — хуже, чем честно показать долю неизвестного.
3. Доля `unattributed` — самостоятельная метрика качества системы.
   Цель первого месяца: опустить её ниже 50%.
